## 四、环境接管：已完成的部分

```
~/fde-journey/
├── app/main.py          只装配：建 app、挂路由、注册 handler
├── app/config.py        配置全部走 FDE_ 前缀环境变量（pydantic-settings）
├── app/api/health.py    /healthz（liveness）+ /readyz（readiness）分层
├── app/core/errors.py   AppError + 统一错误形状 {code, message, request_id}
├── tests/               3 条测试，含一条锁错误契约的
├── pyproject.toml       uv 管理依赖，pytest 覆盖率门槛 50%，ruff 规则集
└── .env.example
```

实测结果（2026-11-04 15:25）：

| 检查                            | 结果                                                  |
| ----------------------------- | --------------------------------------------------- |
| `uv run pytest`               | 3 passed，覆盖率 **91.25%**（门槛 50%）                     |
| `uv run ruff check .`         | All checks passed                                   |
| `uv run uvicorn app.main:app` | 起来，`/healthz` → `{"status":"ok"}`，`/readyz` → ready |
| 结构化日志                         | structlog JSON 输出，`app_start` 事件正常                  |

**为什么这么设计（三条要能讲出来）**：

1. `main.py` 不许有业务逻辑 —— 散进去就是「三个月后自己都读不懂」的头号原因。
2. 健康检查必须分两层 —— 只有一个 `/health`，依赖抖一下就容器反复重启，30 秒故障放大成 10 分钟。
3. 错误形状第一周就钉死 —— 生产里最贵的不是 bug，是每次报错长得都不一样。
